# Quran Hero Kids

منصة تعليمية عائلية تساعد الأطفال على حفظ القرآن الكريم ومراجعته واختبار إتقانهم، مع أدوات متابعة وتحفيز مناسبة للعمر وإشراف الوالدين.

> المشروع في مرحلة تأسيس MVP: توجد API لملفات الأطفال والجلسات موثقة عبر OpenAPI v1، وتبويب تعلّم بمؤقت يسجل جلسة الطفل ويعرض السجل مع إعادة محاولة آمنة. المصادقة الفعلية في Flutter ومحتوى القرآن لم يربطا بعد؛ يلزم دمج Firebase client وإعداد مشروعه لاستخدام API المحمية، ولم يُضف نص أو صوت قرآني قبل اعتماد مصدره. راجع [تدقيق المشروع](docs/PROJECT_AUDIT.md) و[خارطة التنفيذ](docs/IMPLEMENTATION_ROADMAP.md) للحالة الموثقة.

## الهدف

تقديم تجربة آمنة ومشجعة للأطفال بالعربية والإنجليزية، تعمل دون اتصال في وظائف التعلم الأساسية، وتمنح ولي الأمر رؤية عملية للتقدم دون منافسة اجتماعية عامة أو ضغط مفرط على الطفل.

## النطاق الأولي (MVP)

- حساب ولي أمر وإدارة ملفات الأبناء.
- اختيار سورة وآيات، الاستماع، وإعداد جلسات التكرار.
- تسجيل جلسات الحفظ والمراجعة والاختبارات النصية الأولية.
- أهداف يومية، تقدم، نقاط تحفيزية بسيطة، ولوحة ولي الأمر.
- مزامنة خلفية قابلة لإعادة المحاولة؛ دون إدخال الميكروفون أو تحليل التلاوة آليًا في الإصدار الأول.

## التقنية المستهدفة

- تطبيق: Flutter، مع Riverpod وClean Architecture.
- API: ASP.NET Core Web API.
- بيانات: Azure SQL / SQL Server.
- المصادقة: Firebase Authentication مع تحقق الرمز في الخادم.
- التخزين والإشعارات: Azure Blob Storage وFirebase Cloud Messaging عند الحاجة.
- الذكاء الاصطناعي والتعرّف الصوتي مؤجلان إلى ما بعد التحقق من جودة بيانات التلاوة والخصوصية.

## قرارات تأسيسية

- تخزين نص القرآن من مصدر موثوق ذي ترخيص واضح، مع حفظ بيانات المصدر والإصدار والتحقق من النص؛ لا يُنشأ النص القرآني بواسطة نموذج توليدي.
- حساب ولي الأمر هو نقطة التسجيل الأساسية، وملفات الطفل تابعة له ولا تتطلب حسابًا مستقلًا في MVP.
- لا تُطلق منافسة بين الأصدقاء أو مشاركة عامة لبيانات الأطفال ضمن MVP.
- أي تحليل آلي للتلاوة يُعامل كتقييم مساعد قابل للخطأ، ولا يستبدل المعلم أو ولي الأمر.

## التطوير

راجع الخطة في `docs/superpowers/plans/2026-10-14-quran-hero-kids.md` قبل تنفيذ كل مرحلة. لتشغيل API محليًا يلزم .NET 8 SDK: `dotnet run --project backend/src/QuranHero.Api`؛ قاعدة التطوير SQLite تُعرّف فقط في `appsettings.Development.json`. في Development/Testing يمكن فتح Swagger UI على `/swagger` أو مواصفة JSON على `/swagger/v1/swagger.json`؛ الوثائق غير مفعلة في Production. اختبارات الخادم: `dotnet test QuranHeroKids.sln`. لتشغيل الهاتف: `cd mobile && flutter pub get && flutter run --dart-define=API_BASE_URL=https://<عنوان-api>`. لا يصدر التطبيق token حقيقيًا حتى إعداد Firebase وربط `TokenProvider`. تتطلب كل بيئة غير Development/Testing `Firebase__ProjectId` و`ConnectionStrings__QuranHero` من مخزن أسرار البيئة، ويُرفض الإقلاع عند غيابهما. لا يطبق التطبيق migrations تلقائيًا عند بدء الإنتاج؛ ولّد سكربت SQL idempotent وراجعه وطبقه كخطوة نشر منفصلة وفق [إجراء الترحيلات](docs/operations/database-migrations.md). لا تضع قيم الاعتمادات أو سكربتات بيئة حقيقية في Git.
