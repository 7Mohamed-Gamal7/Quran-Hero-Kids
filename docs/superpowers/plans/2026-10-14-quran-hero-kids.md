# Quran Hero Kids Implementation Plan

> **For agentic workers:** نفّذ المهام بالتتابع، وحافظ على خطوات التحقق بعلامات checkbox. لا تُفعّل ميزات الصوت أو الذكاء الاصطناعي للأطفال قبل مراجعة الخصوصية والتحقق من الدقة.

**Goal:** بناء تطبيق عائلي آمن متعدد المنصات لدعم حفظ القرآن ومراجعته ومتابعة التقدم، بدءًا من MVP قابل للاختبار ثم التوسع إلى التلاوة الذكية والتحفيز المتقدم.

**Architecture:** Flutter client يتبع Clean Architecture وRiverpod، ويتواصل مع ASP.NET Core REST API عبر HTTPS. يستخدم الخادم Firebase ID token للتحقق من الهوية وAzure SQL للبيانات العلائقية؛ تُفصل سجلات التقدم والمحتوى القرآني عن ملفات الحساب، وتُصمم المزامنة لتكون قابلة لإعادة المحاولة وآمنة من التكرار.

**Tech Stack:** Flutter/Dart, Riverpod, ASP.NET Core Web API, Entity Framework Core, Azure SQL/SQL Server, Firebase Authentication, OpenAPI, GitHub Actions.

**Spec:** `/home/ubuntu/upload/pasted_content.txt` (المواصفات الأصلية)، و`docs/product/PRD.md` (القرارات ونطاق MVP).

> **سجل التنفيذ اليومي:** حالة المهام الحالية ومعايير القبول وسجل المراجعات موحّدة في [`docs/TASKS.md`](../../TASKS.md). حدّث ذلك الملف بعد كل شريحة؛ تظل هذه الوثيقة مرجع المراحل والاستراتيجية.

## Global Constraints

- يدعم المنتج العربية والإنجليزية واتجاه RTL، وإمكانية تكبير الخط والوضع الداكن.
- ولي الأمر هو الحساب المسجل؛ الطفل ملف تابع لا يملك تسجيل دخول مستقلًا في MVP.
- تخزين بيانات الأطفال بأقل قدر لازم، مع عزل كل قراءة وكتابة بحسب هوية ولي الأمر.
- النص القرآني لا يُولّد آليًا؛ يجب ربط كل نسخة بمصدر موثوق ومراجعة سلامة النص قبل النشر.
- يجب أن تعمل جلسات التعلم الأساسية دون اتصال وأن تُزامن بأمان عند عودة الاتصال.
- لا تُرسل تسجيلات صوت الأطفال إلى خدمة خارجية قبل موافقة صريحة وسياسة احتفاظ ومراجعة امتثال مناسبة.
- لا تُعرض منافسات أو ملفات أطفال للعامة في MVP.

## Review Focus

- محاولة ولي أمر الوصول إلى بيانات طفل تابع لحساب آخر: يجب أن تُرفض من الخادم، ويُختبر ذلك في API integration tests.
- تكرار طلب تسجيل جلسة بسبب انقطاع الشبكة: يجب ألا يكرر النقاط أو التقدم؛ اختبر مفتاح idempotency وإعادة المحاولة.
- مزامنة جلسات غير متصلة بترتيب مختلف: يجب الحفاظ على سجل الأحداث ومنع تراجع التقدم؛ اختبر الترتيب والتعارض.
- اختلاف النص أو رقم الآية/السورة في حزمة المحتوى: يجب رفض البيانات غير المتسقة؛ اختبر تحقق مرجع المحتوى وبصمته.
- حذف ملف طفل أو إلغاء الحساب: يجب تطبيق سياسة حذف/احتفاظ واضحة وإخفاء البيانات عن الواجهات فورًا؛ اختبر تدفق الحذف.

## خريطة الملفات المستهدفة

- `mobile/`: تطبيق Flutter، مقسم إلى `app`, `core`, وميزات مستقلة مثل `auth`, `children`, `quran`, `study`, `progress`.
- `backend/src/QuranHero.Api/`: HTTP endpoints, middleware, OpenAPI.
- `backend/src/QuranHero.Application/`: use cases, validation, ports.
- `backend/src/QuranHero.Domain/`: الكيانات والقواعد الأساسية.
- `backend/src/QuranHero.Infrastructure/`: EF Core, Firebase token validation, adapters.
- `backend/tests/`: اختبارات وحدات وتكامل.
- `database/`: migrations وبيانات مرجعية/seed مضبوطة.
- `docs/`: قرارات المنتج والبنية والأمن والتشغيل.
- `.github/workflows/`: فحوص CI لكل من Dart و.NET والوثائق.
