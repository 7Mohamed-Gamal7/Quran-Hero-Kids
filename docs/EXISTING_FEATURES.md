# Existing Features and Current Status

**As of:** 2026-11-06

Statuses describe implementation in this checkout—not planned architecture or release readiness.

| Area | Status | Evidence and boundary |
|---|---|---|
| Parent identity in backend | **Implemented, live config absent** | `backend/src/QuranHero.Api/Auth/FirebaseAuthenticationExtensions.cs` validates Firebase JWT authority/issuer/audience/lifetime when configured; otherwise auth fails closed. |
| Family ownership | **Implemented** | `ChildrenController` and `StudySessionsController` derive owner UID from verified claims; application services scope reads/writes by owner. Integration tests use test-only auth, not real Firebase-signed tokens. |
| Parent Firebase client auth | **Absent** | No FlutterFire initialization, registration/sign-in/sign-out UI, restored session gate, or Firebase-backed `TokenProvider`. Firebase platform options are absent. |
| Protected API client | **Implemented, fail-closed** | `mobile/lib/src/core/network/api_client.dart` refuses a missing API URL or token; requires HTTPS before attaching Bearer; normalizes send/body-stream failures as `ApiFailureType.network`; maps HTTP status to stable Arabic messages rather than displaying untrusted server details. `ApiException.userMessage` also selects safe fixed messages for configuration/auth/network/JSON decoding, and the child screen does not render the raw exception message. Provider wiring currently returns `MissingTokenProvider`. No live endpoint/TLS was tested. |
| Health probes | **Basic local readiness** | `/health` is process-level liveness; anonymous `/health/ready` calls EF `CanConnectAsync` with a two-second cancellation bound and returns generic 503 on failure. SQLite healthy and closed-loopback SQL Server failure are integration-tested. It does not check schema/migrations or certify a deployed environment. |
| Child profiles | **Implemented** | Flutter screens/repository and authenticated API support list/create/edit/archive. If the write succeeds but its follow-up list refresh fails, the controller preserves the confirmed create/edit/archive result in local view state rather than reporting the write as failed; regression tests cover each mutation. No separate child account exists. |
| Active child selection | **Partial** | Shared in-memory selection is used by family and learning/session flows; archiving the selected child falls back to another active profile or clears the selection, and starting a session on the default profile records it as active. Not persisted or scoped to parent identity across restart. |
| Study session capture/history | **Implemented, network-dependent** | Timer, session kind/duration, stable UUID event ID, history, and same-payload retries are present; concurrent duplicate inserts resolve to one stored session (200 for the matching payload, 409 for a conflicting payload). Integration coverage currently uses SQLite; a 2026-11-03 targeted run passed 13/13 after an initial intermittent SQLite connection-setup error in the concurrency test; fixture diagnosis remains tracked in P3.7. Retry drafts remain screen-memory-only and the production SQL Server provider was not tested live. |
| Offline delivery | **Absent** | No durable outbox, background sync, retry-backoff queue, or conflict UI. |
| Dashboard progress | **Partial** | Home derives count and total duration from the selected child's complete owner-scoped API summary, with explicit no-selection/loading/error states; detailed history remains a separate list and summary refreshes after a successful session save. Greeting uses the matching active child profile name, or a generic greeting if no profile is available. Goals, streaks, and points remain unimplemented; no live API/auth test. |
| Quran text/audio | **Blocked / absent** | `docs/product/content-sources.md` records no owner approval. No source integration or bundled text/audio exists. |
| Tests and achievements | **Placeholder** | Screens state activities are not enabled without approved content and persisted progress. |
| Production migrations | **Separate procedure implemented** | API does not auto-apply production migrations; reviewed SQL is a separate operations step. No production database was accessed. |
| Android Internet permission | **Source manifest fixed in audit slice** | Main manifest previously omitted `INTERNET`; debug/profile manifests included it. Release merged-manifest/build verification remains pending. |
| Accessibility | **Partial, widget-tested** | Narrow-screen/text scaling fixes and semantics for navigation, study timer, and child-profile labels are covered by targeted widget tests; full screen-reader/platform/device, contrast, and release verification remain open. |
| Continuous integration | **Absent in checkout** | `.github/workflows/` does not exist; `.github` has a pull request template. |
| Privacy deletion/export | **Policy/design only** | Security docs call for deletion/export and retention; no end-to-end implementation is evidenced. |
