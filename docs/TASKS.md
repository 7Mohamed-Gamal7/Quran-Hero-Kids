- التحقق الحالي: `dotnet test QuranHeroKids.sln` ناجح (26 اختبارًا)، و`flutter analyze` و`flutter test` ناجحان (13 اختبارًا). اجتاز C# تنسيق `dotnet format whitespace --verify-no-changes`، ولم يبلغ NuGet Audit عن حزم ضعيفة بعد تحديث SQLitePCLRaw وxUnit. راجعنا [تحذير SQLite](https://github.com/advisories/GHSA-2m69-gcr7-jv3q) وإصدار [SQLitePCLRaw bundle 2.1.14](https://www.nuget.org/packages/SQLitePCLRaw.bundle_e_sqlite3/2.1.14)، وتنبيهي [System.Net.Http](https://github.com/advisories/GHSA-7jgj-8wvc-jh57) و[System.Text.RegularExpressions](https://github.com/advisories/GHSA-cmhx-cq75-c4mj).
- غير مهيأ: Firebase project/client credentials، تسجيل الدخول الفعلي، عنوان API منشور، حساب/اعتماد مصدر المحتوى القرآني، مصدر التلاوة، بيئات Azure وCI.
- **بوابة محتوى:** لا تنزيل أو تضمين أو استدعاء مصدر حقيقي قبل موافقة المستخدم على شروط Tanzil أو Quran Foundation أو كليهما. راجع `docs/product/content-sources.md`. لا تولّد نصًا قرآنيًا ولا تعدّل أي نص موثوق.
- **خصوصية:** ملف الطفل يحفظ اسم العرض وفئة عمرية عامة اختيارية، ولا يحفظ تاريخ ميلاد دقيقًا.

## ترتيب التنفيذ

### P0 — تشغيل شريحة منتج مكتملة وآمنة

- [ ] **P0.1 توثيق وتشغيل المصادقة في تطبيق الهاتف:** إضافة تدفق تسجيل/دخول ولي الأمر بالبريد عبر Firebase Auth، وتنفيذ `TokenProvider` حقيقي يعيد Firebase ID token مع حالات sign-in/sign-out وتجديد الجلسة. لا تضمّن إعدادات أو مفاتيح Firebase في Git. أضف اختبارات للـprovider وتدفق الواجهة؛ إن لم توجد إعدادات Firebase، اترك الدمج قابلًا للإعداد ودوّن ما يتطلبه المالك.
  - القبول: لا يصل أي طلب محمي دون token؛ token صالح يرسل `Authorization: Bearer`؛ خروج المستخدم يمسح الحالة المحلية؛ لا توجد بيانات اعتماد في المستودع.
- [x] **P0.2 إكمال دورة جلسة التعلم في Flutter:** شاشة/حالة بدء، إيقاف/إنهاء، نوع الجلسة ومدتها و`clientEventId` ثابت لكل حدث، ثم إرسالها إلى `/api/v1/children/{id}/study-sessions` وعرض سجل الجلسات مع حالات الشبكة والأخطاء. **منجز في `c1a92f4`:** مؤقت في تبويب التعلم، اختيار طفل/نوع نشاط، سجل جلسات، UUID v4، وإعادة محاولة تحتفظ بنفس الحمولة والمعرّف.
  - القبول: الإعادة تحتفظ بنفس event ID ولا تنشئ سجلًا ثانيًا؛ معرف طفل من أسرة أخرى لا يكشف بيانات؛ اختبارات widget/repository تغطي دورة الجلسة.
- [x] **P0.3 جعل API schema والاختبارات جزءًا من العقد:** **مكتملة في `ec33e11`.** أضيف OpenAPI v1 مع متطلبات Bearer على المسارات المحمية فقط، واستجابات request/response والأخطاء والقيود؛ وثيقة Swagger متاحة في Development/Testing وليست مفعلة في Production.
  - التحقق: 26 اختبار .NET ناجح؛ اختبارات 401 على جميع عمليات API المحمية، و404 على عمليات الطفل/الجلسة بمعرف غير موجود، و409 لإعادة المحاولة المتعارضة، وحدود الاسم والعمر والمدة والوقت وlimit، مع اختبار مباشر لمخطط OpenAPI. فحص مصدر backend لم يجد تسجيل payload أو token أو اسم طفل عبر logger/Console/HTTP logging.
- [ ] **P0.4 ضبط الترحيلات والتهيئة:** توثيق خطوات نشر migration، منع تشغيل عمليات تغيير schema عشوائية عند startup إن لزم، وإضافة تحقق بدء يمنع Production بلا Firebase Project ID أو Azure SQL connection. لا تضع أسرارًا حقيقية في الإعدادات أو السجلات.
  - القبول: يعمل SQLite في Development/Testing وSQL Server فقط خارجها؛ migration script قابل للتوليد؛ الإعداد الإنتاجي الناقص يفشل بإشارة آمنة وواضحة.

**حاجز P0.1:** لا توجد إعدادات Firebase للعميل ولا Firebase ID token حقيقي في الجلسة؛ لذلك تحقق التطوير عبر repository/widget tests، وليس اتصالًا حيًا بـAPI. لا تضمّن بيانات اعتماد تخمينية. يبقى تسليم الجلسات عبر شبكة غير موثوقة قابلًا لإعادة المحاولة ما دامت الشاشة حية؛ لا توجد قائمة انتظار محلية دائمة حتى P2.5.

  - القبول: مطابقة مرجع المصدر؛ أدوات وصول مناسبة؛ لا placeholder يوهم بوجود محتوى حقيقي.

1. راجع الفرع والـcommit والحالة البعيدة، ثم اقرأ هذا الملف وREADME ووثائق المنتج والبنية والبيانات والأمن ومصادر المحتوى.

4. نفّذ شريحة صغيرة واضحة، أضف/حدّث الاختبارات، شغّل كل الفحوص ذات الصلة، ثم حدّث checkboxes ونتائج التحقق وقيود الاعتماد في هذا الملف.
5. بعد نجاح الاختبارات، سجّل Conventional Commit وادفع إلى `master` إذا سمحت صلاحيات المستودع وكانت الشريحة مكتملة. لا ترفع أسرارًا أو إعدادات محلية، ولا تدّع إتمام فحوص لم تُشغّل.
6. إذا حُجبت مهمة بموافقة محتوى أو اعتماد أو صلاحية أو قرار منتج، وثّق الحاجز، وانتقل إلى مهمة مستقلة قابلة للتنفيذ بدل اختراع قرار أو تجاوز المنع.
7. إذا اكتملت كل المهام المفتوحة، نفّذ تدقيقًا شاملًا جديدًا للمشروع (الجودة، الأمان، UX، الاختبارات، الاعتماديات، الإطلاق)، أضف فجوات ومهام جديدة مبررة إلى هذا الملف، ثم استأنف من أعلى أولوية.
