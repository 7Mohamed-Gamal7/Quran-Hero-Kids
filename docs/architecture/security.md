# الأمن والخصوصية — خط أساس

هذه وثيقة تصميم وليست إثبات امتثال. يجب تحديد الأسواق المستهدفة وإجراء مراجعة قانونية/خصوصية قبل إطلاق التطبيق للأطفال.

## الهوية والتفويض

- ولي الأمر يسجل الدخول لدى موفر هوية؛ يتحقق API من التوقيع والمصدر والجمهور والانتهاء في كل طلب.
- لا يُعامل `parentId` أو `childId` الوارد من العميل كدليل صلاحية.
- يفرض الخادم ملكية الأسرة على كل قراءة وكتابة، مع اختبارات سلبية عبر حسابين مختلفين.
- صلاحيات منفصلة للعميل وموظفي الدعم/الإدارة، ومصادقة قوية وأقل امتياز للعمليات الإدارية.

## تقليل البيانات

- جمع ما يلزم للتعلم فقط؛ الاسم المعروض والفئة العمرية العامة والمستوى تكفي غالبًا. لا يُجمع تاريخ ميلاد دقيق في MVP.
- الفئات العمرية الأولية الواسعة في التطبيق هي `5-7` و`8-10` و`11-13` و`14+`؛ يمكن تعديلها بعد مراجعة ملاءمة الأعمار المستهدفة.
- صورة الطفل اختيارية وغير مطلوبة في MVP.
- لا تسجيل صوتي ولا دردشة ولا موقع جغرافي ولا ملف عام في الإصدار الأول.
- لا تستخدم بيانات الطفل للتسويق أو الإعلانات الموجهة.

## التخزين والنقل

- HTTPS/TLS لجميع الاتصالات؛ تشفير التخزين وإدارة المفاتيح عبر خدمات المنصة.
- أسرار Firebase/Azure/CI خارج المستودع، وتدويرها وفق سياسة تشغيل.
- تخزين محلي مشفر للبيانات الحساسة عند الحاجة، مع مسحها عند تسجيل الخروج أو حذف الملف.
- نسخ احتياطية مشفرة واختبارات استعادة موثقة.

## السجلات والتحليلات

- لا تسجل أسماء الأطفال أو البريد أو نصوص التلاوة أو الرموز السرية.
- استخدم معرفات ارتباط غير مباشرة، واحتفاظ محدود بالسجلات.
- القياسات التحليلية اختيارية/مجمعة، مع احترام موافقة ولي الأمر وضوابط المنتج.

## موافقة ولي الأمر والاحتفاظ والحذف

- واجهة واضحة لشرح البيانات والغرض ومدة الاحتفاظ قبل تفعيل ميزات الطفل.
- آلية تصدير/حذف قابلة للتنفيذ، وسياسة دورة حياة تحدد أثر الحذف على النسخ الاحتياطية.
- الإشعارات للأطفال تحت تحكم ولي الأمر؛ لا تُفعّل افتراضيًا بما يخالف الإعداد.
- قبل الإطلاق، راجع قوانين حماية الأطفال والخصوصية في كل سوق (بما فيها COPPA حيث ينطبق، ومتطلبات GDPR/UK GDPR أو القوانين المحلية بحسب السوق) مع مستشار مؤهل.

## أمن التطبيق والواجهة البرمجية

- تحقق من النوع والحجم والمدى، تحديد معدل الطلبات، حماية من إعادة الاستخدام، ورسائل خطأ لا تكشف بيانات.
- فحص التبعيات والشيفرة والأسرار في CI، وتحديثات أمنية دورية.
- سياسة CORS محدودة، رؤوس آمنة، وضبط صلاحيات التخزين السحابي.
- خطة استجابة للحوادث تشمل العزل، التقييم، الإشعار حيث يلزم، والاستعادة.

## سلامة المحتوى القرآني والصوت

- النص القرآني مصدر موثوق ثابت الإصدار، مع checksum واختبارات مقارنة قبل نشر أي تحديث.
- تراخيص النص والتلاوات والتنزيل تؤكد وتوثق قبل التوزيع.
- أي تصحيح تلقائي مستقبلي يُعرض كمساعدة غير نهائية، مع مسار رجوع لولي الأمر/المعلم ومراجعة دقة على لهجات وأعمار مختلفة.
